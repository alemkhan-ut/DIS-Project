Сценарий собирается в инспекторах, без кода: шаги, режимы (тренировка, экзамен), события, условия и нарушения, логгер, анализатор. Прохождение пишется в журнал, журнал можно переоценить другим анализатором.

Инструменты редактора доступны в меню **Tools → ScenarioKit**:
- **Сценарии (Scenario Definition)** — модальное окно выбора со списком всех `ScenarioDefinition` в проекте, детальным просмотром шагов и режимов, быстрой привязкой к `ScenarioRunner` на сцене и возможностью создать свой сценарий (через встроенную форму или диалог сохранения).
- **Журналы прохождений** — окно просмотра и переоценки журналов прохождения сценариев различными анализаторами.

## 1. Быстрый старт

1. Откройте проект в Unity 6000.3.21f1.
2. Откройте сцену `Assets/ScenarioKit/Demo/Scenes/ScenarioDemo.unity`.
3. Нажмите Play. Появится панель «Учебный сценарий» с кнопками режимов: «Тренировка», «Тренировка (по порядку)», «Экзамен».
4. Выберите режим. Слева — режим, группа и список активных заданий.
5. Управление: **WASD** или стрелки — движение игрока. Кнопки «Пульта управления» (Питание, Тревога, Сигнал, Проверка, Насос, Отчёт), тумблеры «Свет» и «Клапан» нажимаются мышью.
6. После последнего шага показывается итог. На панели итога: «Переоценить» (с выбором анализатора), «Загрузить последний журнал», «Показать журнал», «Пройти заново», «Выбрать режим». Во время прохождения доступны «Пройти заново» и «Прервать».

Журналы пишутся в `<Application.persistentDataPath>/ScenarioLogs/` (файл `<сценарий>_<режим>_<yyyyMMdd_HHmmss_fff>.json`; папку задаёт поле логгера JSON-файла, её же используют «Загрузить последний журнал» и «Открыть папку журналов»). В Editor их удобно смотреть в окне **Tools → ScenarioKit → Журналы прохождений**.

### Сцена

| Объект | Что делает |
|---|---|
| Player | Движется по WASD, тег `Player` |
| Zone A (−6, 0), Zone B (−6, 6), Zone C (6, −4), Zone D (6, 6) | Триггеры: `ZoneA_Enter` … `ZoneD_Enter` (внутри каждой зоны видна её буква A, B, C, D) |

### Демонстрационный сценарий (`Demo/Data/DemoScenario.asset`, 12 шагов)

| Шаг | Что сделать | Событие |
|---|---|---|
| `power_on` | Нажать «Питание» (нарушение: «Тревога») | `Btn_Power` |
| `light_on` | Включить тумблер «Свет» | `Toggle_Light_On` |
| `enter_zone_c` | Войти в зону C | `ZoneC_Enter` |
| `push_box` | Толкнуть ящик, не задев стену (нарушение: `Wall_Hit`) | `Box_Hit` |
| `route_a_b` | Зона A, затем зона B, строгий порядок | `ZoneA_Enter` → `ZoneB_Enter` |
| `pump_start` | Нажать «Насос» при открытом клапане (условие: `Valve_Open`) | `Btn_Pump` |
| `check` | Нажать «Проверка» | `Btn_Check` |
| `touch_marker` | Коснуться сферы | `Marker_Hit` |
| `enter_zone_d` | Войти в зону D | `ZoneD_Enter` |
| `signal` | Нажать «Сигнал» (нарушение: «Тревога») | `Btn_Signal` |
| `report` | Нажать «Отчёт» | `Btn_Report` |
| `close_valve` | Закрыть клапан (выключить тумблер «Клапан») | `Valve_Closed` |

Режимы:

- **Тренировка** (`Training_Mixed`): стадии идут по очереди. Стадия 1 — `power_on`, `light_on`, `enter_zone_c`, `push_box` одновременно. Затем по одной: `route_a_b`, `pump_start`, `check`, `touch_marker`. Затем `enter_zone_d` + `signal` одновременно, затем `report` + `close_valve` одновременно. Нарушение — повтор шага. Анализатор — «тренировка».
- **Тренировка (по порядку)** (`Training_Sequential`): те же 12 шагов строго по одному. Действие раньше очереди просто не засчитывается.
- **Экзамен** (`Exam`): три группы по очереди. «Подготовка» — 4 шага одновременно. «Запуск» — `route_a_b`, `pump_start`, `check`, `touch_marker` по очереди. «Завершение» — `enter_zone_d` + `signal`, затем `report` + `close_valve`. Порог — 2 нарушения в группе. Анализатор — «экзамен».

## 2. Инструкция для пользователя (настройка и запуск без кода)

Все настройки сценария, шагов, режимов и оценивания производятся через визуальный интерфейс Unity Editor без программирования.

### 2.1 Как открыть сцену
1. В окне **Project** (внизу экрана) откройте папку `Assets/ScenarioKit/Demo/Scenes/`.
2. Дважды кликните по сцене **`ScenarioDemo.unity`**.

### 2.2 Как запустить сценарий
1. В верхней панели Unity нажмите кнопку **Play** (▶).
2. На экране появится стартовое меню — кликните по желаемому режиму: **«Тренировка»**, **«Тренировка (по порядку)»** или **«Экзамен»**.
3. В левой части экрана появится список текущих активных заданий.
4. **Управление в игре:**
   - **WASD** или стрелки клавиатуры — перемещение персонажа;
   - **Мышь** — клик по кнопкам на пульте управления («Питание», «Сигнал», «Насос» и др.) и тумблерам («Свет», «Клапан»);
   - Толкание ящика — просто подойдите и упритесь в него персонажем;
   - Вход в зоны (A, B, C, D) — войдите персонажем в цветной квадрат зоны на полу.

### 2.3 Как изменить порядок и активацию шагов
Откройте сценарий через меню **Tools → ScenarioKit → Сценарии** (или выделите файл `DemoScenario.asset` в папке `Demo/Data/`). В секции «Режимы» нажмите на нужный режим — откроется визуальный редактор:
- **Порядок шагов:** перетаскивайте цветные плашки («чипы») шагов мышью между стадиями или меняйте сами стадии кнопками **▲** и **▼**.
- **Одновременная активация:** поместите несколько шагов в одну стадию (перетащите их друг к другу или выберите в меню стадии **«⋮» → «Объединить со следующей»**). Все шаги одной стадии активны сразу и могут выполняться в любом порядке.
- **Последовательная активация:** разместите шаги по отдельным стадиям (или выберите в меню группы **«⋮ Действия» → «Все шаги по очереди»**). Следующий шаг откроется только после выполнения предыдущего.
- **Смешанная активация:** комбинируйте стадии — часть стадий делайте групповыми (выполняются в свободном порядке), часть — одиночными (строго по очереди).

### 2.4 Как настроить группы шагов
В режимах с несколькими этапами (например, в «Экзамене»):
- **Добавить группу:** нажмите кнопку **«＋ Группа»** и введите название.
- **Распределить шаги:** просто перетаскивайте шаги мышью между группами.
- **Порог ошибок в группе:** ползунком **«Порог нарушений в группе»** задайте лимит ошибок (например, `2`). При достижении порога группа немедленно завершается, а оставшиеся в ней шаги помечаются как пропущенные.

### 2.5 Как изменить режим прохождения
- **При запуске сцены:** режим выбирается кликом по кнопке в меню на экране.
- **По умолчанию в инспекторе:** выделите объект **Scenario Runner** на сцене и в поле **«Режим при запуске»** выберите нужный режим из списка.
- **Создать новый режим:** в окне сценария нажмите кнопку **«＋ Тренировка»** или **«＋ Экзамен»**.

### 2.6 Как настроить обработку событий (кнопки, зоны, столкновения)
Чтобы шаг сценария реагировал на действие, выделите объект на сцене и добавьте компонент (**Add Component** в инспекторе):
- **Кнопка UI:** компонент `ButtonEventSource` → в поле «Событие при нажатии» выберите ключ события (например, `Btn_Power`).
- **Зона триггера:** компонент `TriggerEventSource` (на объекте с Collider и галочкой *Is Trigger*) → выберите события входа и выхода.
- **Столкновение (толчок ящика, удар о стену):** компонент `CollisionEventSource` → выберите событие удара.
- **Тумблер (состояние переключателя):** компонент `ToggleStateSource` → укажите ключ состояния (например, `Valve_Open`), которое проверяется в условии шага («Только если клапан открыт»).

*Ключи событий и состояний выбираются из выпадающего списка; кнопка «＋ Создать…» позволяет добавить новый ключ прямо на месте.*

### 2.7 Как настроить логгер и анализатор
1. Выделите объект **Scenario Runner** на сцене:
   - **Логгер:** в поле «Логгер» выберите `JsonFileLogger` (сохраняет файлы журналов на диск) или `MemoryLogger` (хранит лог только в оперативной памяти). Имя папки задаётся в ассете логгера (`Demo/Data/Loggers`).
   - **Анализатор:** задаётся в свойствах каждого режима в поле «Анализатор по умолчанию».
2. **Настройка системы оценки:** выделите ассет анализатора в папке `Demo/Data/Analyzers`:
   - У тренировки: баллы за первую и последующие попытки (по умолчанию `10, 5`);
   - У экзамена: начальный балл (`100`), штраф за ошибку (`10`) и штраф за пропуск шага (`5`).

### 2.8 Как посмотреть журнал и результат
1. **В игре (HUD):**
   - По окончании прохождения автоматически откроется окно **Результаты** с набранными баллами и цветной подсветкой статусов (зелёный — выполнен/успех, красный — не выполнен/ошибка).
   - Кнопка **«Показать журнал»** откроет детальный лог всех событий по единому шаблону `[Время] Тип - Сообщение`.
   - В выпадающем списке анализаторов можно переключить анализатор и нажать **«Переоценить»**, чтобы пересчитать результат по другим правилам.
2. **В редакторе Unity:**
   - Откройте окно **Tools → ScenarioKit → Журналы прохождений**.
   - Выберите файл журнала в списке слева — справа отобразится подробный цветной результат оценки выбранным анализатором и список всех записей.

## 3. Контрольные примеры ТЗ §7

Обе последовательности ниже проверены прогоном через `ScenarioSession` на демо-ассетах. Для воспроизведения удобнее всего симуляция событий в инспекторе раннера (2.10) или реальные кнопки HUD. При ходьбе не заходите в зоны и не касайтесь объектов раньше их стадии: это лишние действия, которые меняют итог. Игрок стартует в (0, 0, −8); ящик в (0, 0), стена в (3, 0).

### 3.1 Тренировка: 105 / 120

Режим «Тренировка». Максимум 12 шагов × 10 = 120. Действия выполняйте строго в этом порядке: шаги активируются по стадиям, а действие шага до его стадии в этом режиме считается лишней попыткой.

1. Стадия 1 (`power_on`, `light_on`, `enter_zone_c`, `push_box`): нажмите «Питание», включите «Свет», зайдите в зону C. Затем заденьте стену (`Wall_Hit`, нарушение `push_box`) и толкните ящик (`Box_Hit`): `push_box` выполнен со 2-й попытки.
2. Стадия 2 (`route_a_b`): зайдите в зону A, затем в зону B.
3. Стадия 3 (`pump_start`): откройте «Клапан», затем нажмите «Насос».
4. Стадия 4 (`check`): нажмите «Проверка».
5. Стадия 5 (`touch_marker`): коснитесь сферы.
6. Стадия 6 (`enter_zone_d`, `signal`): зайдите в зону D. Дважды нажмите «Тревога» (два нарушения `signal`), затем «Сигнал»: `signal` выполнен с 3-й попытки. «Питание» к этому моменту уже выполнено, поэтому «Тревога» нарушает только `signal`.
7. Стадия 7 (`report`, `close_valve`): нажмите «Отчёт», закройте «Клапан».

Баллы: `power_on` — 10, `push_box` (попытка 2) — 5, `signal` (попытка 3) — 0, остальные 9 шагов с первой попытки — 9 × 10 = 90.

Итог: 10 + 5 + 0 + 90 = **105 / 120**.

### 3.2 Экзамен: 70 / 100

Режим «Экзамен». Порог — 2 нарушения в группе.

1. Группа «Подготовка» (все 4 шага активны сразу): нажмите «Тревога» (нарушение — `power_on` провален), затем заденьте стену (нарушение — `push_box` провален). Порог 2 достигнут, группа завершается досрочно: `light_on` и `enter_zone_c` пропущены (`Skipped`). «Питание», «Свет» и зону C не трогайте.
2. Группа «Запуск», по стадиям: зайдите в зону A, затем в зону B; откройте «Клапан», затем нажмите «Насос» (клапан изначально закрыт, «Насос» без открытого клапана провалит `pump_start`); нажмите «Проверка»; коснитесь сферы.
3. Группа «Завершение», по стадиям: зайдите в зону D, нажмите «Сигнал»; нажмите «Отчёт», закройте «Клапан».

Действие шага из ещё не начатой группы или стадии в экзамене считается нарушением порядка и проваливает шаг, поэтому соблюдайте порядок.

Итог: 100 − 2 × 10 (проваленные шаги) − 2 × 5 (пропущенные) = **70 / 100**.

## 4. Техническое описание

### 4.1 Поток данных

```
Источники (MonoBehaviour)  →  ScenarioEventBus  →  ScenarioSession  →  журнал  →  анализатор
  Button/Trigger/Collision      (статическая шина      (чистый C#,         (ScenarioLog,     (TrainingAnalyzer,
  UnityEvent/ToggleState         событий + состояние    без Unity API)      IScenarioLogger)  ExamAnalyzer)
                                 мира)
```

- **События** (`Assets/ScenarioKit/Runtime/Events`): `ScenarioEventKey`, `ScenarioStateKey`, `ScenarioEventBus` (шина и состояние мира, `IWorldState`).
- **Источники** (`Runtime/Sources`): превращают действия Unity в события шины.
- **Шаги** (`Runtime/Steps`): `StepDefinition` — данные шага, `StepTracker` — состояние одного шага в сессии, `StepVerdict` — ответ трекера (ничего / прогресс / выполнен / нарушение).
- **Режимы** (`Runtime/Modes`): `ScenarioMode` → `TrainingMode`, `ExamMode`; `StepGroup` → `ActivationStage` → шаги.
- **Сессия** (`Runtime/Execution/ScenarioSession.cs`): чистый C#. Ведёт активацию стадий и групп, обрабатывает нарушения (повтор в тренировке, Failed/Skipped и порог в экзамене), пишет журнал.
- **Раннер** (`ScenarioRunner`): MonoBehaviour, мост между сценой и сессией. Запуск, прерывание, `SimulateEvent`, `Analyze`, `LastLog`, `LastResult`, `CurrentLog`.
- **Журнал** (`Runtime/Logging`): `ScenarioLog`, `LogRecord`, `IScenarioLogger`, `MemoryScenarioLogger`, `JsonFileScenarioLogger`.
- **Анализаторы** (`Runtime/Analysis`): читают только журнал, не сессию.
- **Валидатор** (`Runtime/Validation/ScenarioValidator.cs`): проверяет сценарий, результаты показывает инспектор.

Ядро (сессия, анализаторы, журнал) не использует `MonoBehaviour` и `UnityEditor`. Сборки: `ScenarioKit.Runtime`, `ScenarioKit.Editor` (только Editor), `ScenarioKit.Demo`.

### 4.2 Как добавить новое

- **Новый тип шага.** Создайте класс-наследник `StepDefinition` с атрибутом `[CreateAssetMenu(menuName = "ScenarioKit/…")]`, реализуйте `SuccessEvents`, `IsTriggeredBy(key)` и `CreateTracker()`. Трекер — наследник `StepTracker`: `Handle(key, world)` возвращает `StepVerdict` (`None`, `Progress`, `Completed` или нарушение), `Reset()` сбрасывает прогресс. Тип сразу появится в «＋ Новый шаг» (список типов берётся из `TypeCache`), для него работает общий инспектор. Образец — `Runtime/Steps/EventStep.cs`.
- **Новый режим.** Наследник `ScenarioMode`: `Groups`, `RetryAfterViolation`, при необходимости `ShouldSkipRestOfGroup(n)`. Образцы — `TrainingMode`, `ExamMode`.
- **Новый логгер.** Класс, реализующий `IScenarioLogger` (`Write`, `Complete`), и ассет-наследник `ScenarioLoggerAsset` с `Create(header)`. Образец — `JsonFileLoggerAsset`.
- **Новый анализатор.** Наследник `ScenarioAnalyzer` с `Analyze(ScenarioLog)`, возвращает `AnalysisResult`. Образец — `TrainingAnalyzer`. Подсказка: `LogDigest.Create(log)` сворачивает журнал в факты по шагам.
- **Новый источник.** Наследник `ScenarioEventSource` (или отдельный MonoBehaviour) вызывает `ScenarioEventBus.Raise(key)`. Образцы — `ButtonEventSource`, `TriggerEventSource`.

### 4.3 Контракт журнала

Формат: JSON через `JsonUtility`, `FormatVersion = 1`.

```
ScenarioLog { FormatVersion, ScenarioId, ModeName, StartedUtc, StepIds[], Records[] }
LogRecord   { Time, Type, StepId, Result, Message, Data[{Key, Value}] }
```

`Time` — секунды от старта сессии. Типы записей (`LogRecordTypes`): `ScenarioStarted`, `GroupStarted`, `GroupFinished`, `StepActivated`, `StepCompleted`, `Violation`, `StepFailed`, `StepSkipped`, `ScenarioFinished`, `ScenarioAborted`. Анализатор получает только `ScenarioLog`, поэтому оценить можно любой сохранённый файл и любым анализатором.

`AnalysisResult`: `AnalyzerName`, `Score`, `MaxScore`, `Steps[]` (`StepScore`: `StepId`, `Status` — `Completed`/`Failed`/`Skipped`/`NotCompleted`, `Attempts`, `Points`; в текстовом отчёте `ReportFormatter` статусы выводятся по-русски: «выполнен», «провален», «пропущен», «не выполнен»), `Warnings[]`. Публичные поля — PascalCase, как в DTO журнала.

## 5. Принятые решения

- **«Вне очереди».** В тренировке действие раньше очереди — попытка шага (повтор, штраф баллами). В экзамене — Failed своей группы. Режим может вместо этого просто игнорировать такие действия.
- **Нарушение в экзамене.** `ExamAnalyzer` считает Failed любой шаг, у которого есть нарушения, даже если он потом выполнен.
- **Обработка событий по снимку статусов.** Событие обрабатывается относительно статусов, зафиксированных до его прихода. Шаги, ставшие активными из-за этого же события, его не видят.
- **Одно событие — выполнение и «вне очереди».** Если ждущий (ещё не активный) шаг получил событие, которое уже принял активный шаг в том же событии, «вне очереди» ему не засчитывается. Это нужно, когда одно событие завершает стадию и одновременно относится к следующей.
- **Старт сессии.** Сначала вызывается «Перед стартом сессии» (`onBeforeSessionStart`), затем состояние мира сбрасывается, и тумблеры (`ToggleStateSource`) заново пишут своё состояние. Поэтому начальные значения, заданные в обработчике, не теряются.
- **Результаты.** `StepScore` и `AnalysisResult` — публичные поля PascalCase (`StepId`, `Status`, `Attempts`, `Points`; `AnalyzerName`, `Score`, `MaxScore`, `Steps`, `Warnings`).
- **Живая лента.** `ScenarioRunner.CurrentLog` — заголовок журнала текущей сессии для ленты записей в инспекторе. Сторонний логгер, не пишущий в этот заголовок, покажет пустую ленту.
- **Порядок стадий** меняется кнопками ▲ ▼, а не ручкой перетаскивания. Перетаскиваются шаги.
- **Автотестов нет.** Решение автора. Работа проверялась вручную (ниже).

### Как проверено

- Консоль Unity без ошибок и предупреждений из `Assets/ScenarioKit` после каждой задачи.
- Контрольные примеры раздела 3 прогнаны через `ScenarioSession` на реальных демо-ассетах (через Unity MCP): тренировка 105 / 120, экзамен 70 / 100. `ExamAnalyzer` на пустом журнале даёт 0 / 100 с предупреждением «Журнал пуст».
- Перетаскивание в инспекторах (чипы между стадиями и группами, из окна Project) проверено по коду и программными вызовами операций редактирования, но не мышью. Первое открытие сценария мышью стоит проверить.
