# ScenarioKit — конструктор учебных сценариев

Unity 6000.3.21f1, C#, URP. Только стандартные пакеты Unity. Ввод — новый Input System.

Сценарий собирается в инспекторах, без кода: шаги, режимы (тренировка, экзамен), события, условия и нарушения, логгер, анализатор. Прохождение пишется в журнал, журнал можно переоценить другим анализатором.

## 1. Быстрый старт

1. Откройте проект в Unity 6000.3.21f1.
2. Откройте сцену `Assets/ScenarioKit/Demo/Scenes/ScenarioDemo.unity`.
3. Нажмите Play. Появится панель «Учебный сценарий» с кнопками режимов: «Тренировка», «Тренировка (по порядку)», «Экзамен».
4. Выберите режим. Слева — режим, группа и список активных заданий.
5. Управление: **WASD** или стрелки — движение игрока. Кнопки «Пульта управления» (Питание, Тревога, Сигнал, Проверка, Насос, Отчёт), тумблеры «Свет» и «Клапан» нажимаются мышью.
6. После последнего шага показывается итог. На панели итога: «Переоценить» (с выбором анализатора), «Загрузить последний журнал», «Показать журнал», «Пройти заново», «Выбрать режим». Во время прохождения доступны «Пройти заново» и «Прервать».

Журналы пишутся в `<Application.persistentDataPath>/ScenarioLogs/` (файл `<сценарий>_<режим>_<yyyyMMdd_HHmmss>.json`). В Editor их удобно смотреть в окне **Tools → ScenarioKit → Журналы прохождений**.

### Сцена

| Объект | Что делает |
|---|---|
| Player | Движется по WASD, тег `Player` |
| Zone A (−6, 0), Zone B (−6, 6), Zone C (6, −4), Zone D (6, 6) | Триггеры: `ZoneA_Enter` … `ZoneD_Enter` |
| Pushable Box (0, 0) | Столкновение с игроком: `Box_Hit` |
| Wall (3, 0) | Столкновение с игроком: `Wall_Hit` |
| Marker Sphere (−2, −4) | Касание игроком: `Marker_Hit` |
| Scenario Runner | Запускает режимы, пишет журнал |
| Scenario Hud | Весь интерфейс |

### Демонстрационный сценарий (`Demo/Data/DemoScenario.asset`, 12 шагов)

| Шаг | Что сделать | Событие |
|---|---|---|
| `power_on` | Нажать «Питание» (нарушение: «Тревога») | `Btn_Power` |
| `light_on` | Включить тумблер «Свет» | `Toggle_Light_On` |
| `enter_zone_c` | Войти в зону C | `ZoneC_Enter` |
| `push_box` | Толкнуть ящик, не задев стену (нарушение: `Wall_Hit`) | `Box_Hit` |
| `route_a_b` | Зона A, затем зона B, строгий порядок | `ZoneA_Enter` → `ZoneB_Enter` |
| `pump_start` | Нажать «Насос» при открытом клапане (условие: `Valve_Open`) | `Btn_Pump` |
| `check` | Нажать «Проверка» | `Btn_Check` |
| `touch_marker` | Коснуться сферы | `Marker_Hit` |
| `enter_zone_d` | Войти в зону D | `ZoneD_Enter` |
| `signal` | Нажать «Сигнал» (нарушение: «Тревога») | `Btn_Signal` |
| `report` | Нажать «Отчёт» | `Btn_Report` |
| `close_valve` | Закрыть клапан (выключить тумблер «Клапан») | `Valve_Closed` |

Режимы:

- **Тренировка** (`Training_Mixed`): стадии идут по очереди. Стадия 1 — `power_on`, `light_on`, `enter_zone_c`, `push_box` одновременно. Затем по одной: `route_a_b`, `pump_start`, `check`, `touch_marker`. Затем `enter_zone_d` + `signal` одновременно, затем `report` + `close_valve` одновременно. Нарушение — повтор шага. Анализатор — «тренировка».
- **Тренировка (по порядку)** (`Training_Sequential`): те же 12 шагов строго по одному. Действие раньше очереди просто не засчитывается.
- **Экзамен** (`Exam`): три группы по очереди. «Подготовка» — 4 шага одновременно. «Запуск» — `route_a_b`, `pump_start`, `check`, `touch_marker` по очереди. «Завершение» — `enter_zone_d` + `signal`, затем `report` + `close_valve`. Порог — 2 нарушения в группе. Анализатор — «экзамен».

## 2. Настройка без кода, по инспекторам

Все ассеты создаются из меню **Create → ScenarioKit → …** (или кнопками «＋ Создать…» в инспекторах): «Сценарий», «Шаг (по событиям)», «Событие», «Состояние», «Режим: тренировка», «Режим: экзамен», «Логгер: JSON-файл», «Логгер: в памяти», «Анализатор: тренировка», «Анализатор: экзамен».

Общие правила инспекторов:

- Каждая ссылка на ассет ScenarioKit — выпадающий список подходящих ассетов с пунктом «＋ Создать…» и кнопкой показа в Project.
- Ошибки валидатора выводятся вверху инспектора сценария (`HelpBox`), проблемная строка подсвечена. Правки поддерживают Undo.
- Подписи и подсказки на русском.

### 2.1 Центр управления сценарием

Выделите `DemoScenario.asset`. Инспектор содержит:

1. **Сценарий** — идентификатор, число шагов и режимов, статус проверки.
2. **Проверка сценария** — список ошибок и предупреждений, кнопка «Показать» выделяет проблемный объект.
3. **Шаги сценария (библиотека)** — список шагов. Рядом с каждым — «где используется». Клик по шагу открывает его редактор ниже. Кнопка «＋ Новый шаг» создаёт шаг выбранного типа. Шаги из окна Project можно перетащить в список.
4. **Режимы** — кнопки «＋ Тренировка», «＋ Экзамен», «＋ Существующий». Клик по режиму открывает его редактор ниже.
5. **Редактирование: …** — встроенный инспектор выбранного шага или режима. Отдельно открывать ассеты не нужно.

### 2.2 Создание и редактирование шага

«＋ Новый шаг» в сценарии (или Create → ScenarioKit → Шаг (по событиям)). Поля:

- **Идентификатор** — уникальное имя шага, попадает в журнал. «↺ из имени файла» подставляет имя ассета.
- **Текст задания для пользователя** — показывается в списке заданий.
- **Последовательность** — события, которые нужно выполнить; «Строгий порядок» требует их строго по списку.
- **Только если** (условия) — состояния мира, которые должны совпасть в момент события.
- **Считать нарушением** — события-нарушения со своим сообщением.
- Внизу — итоговая фраза **«Шаг выполнен, когда: …»** и «Где используется».

### 2.3 События, условия и нарушения

- **Событие** (`ScenarioEventKey`) — именованный ключ, например `Btn_Power`. Создаётся в выпадающем списке «Событие» через «＋ Создать…».
- **Состояние** (`ScenarioStateKey`) — флаг мира «включено / выключено», например `Valve_Open`. Его пишет `ToggleStateSource` (компонент на Toggle). Условие шага: «Состояние — включено/выключено».
- **Нарушение** — событие из списка «Считать нарушением». При нём шаг записывает нарушение с вашим сообщением (в UI оно показывается 3 секунды). Условие, не совпавшее в момент нужного события, — тоже нарушение с сообщением «Не выполнено условие» (текст настраивается).

### 2.4 Перетаскивание шагов между стадиями и группами

Выберите режим в центре управления. Режим состоит из групп (экзамен — несколько, тренировка — одна), группа из стадий, стадия из шагов. Стадии идут по очереди, шаги одной стадии активны одновременно.

- Шаги — «чипы». Тяните чип мышью между стадиями и группами. Чипы из окна Project можно бросать прямо в стадию.
- «＋ Перетащите шаг сюда, чтобы создать новую стадию» — бросьте шаг на эту область.
- Порядок стадий меняют кнопки **▲ ▼**. Шаг убирается кнопкой «✕» (вернётся в список свободных шагов «Шаги сценария, которые ещё не в режиме»).
- «＋ Группа» добавляет группу в экзамен.

### 2.5 Быстрые действия «одновременно / по очереди»

Меню **«⋮ Действия»** группы:

- «Все шаги одновременно» — все шаги группы в одну стадию.
- «Все шаги по очереди» — каждый шаг в свою стадию.
- «Удалить пустые стадии», «Удалить группу».

Меню **«⋮»** стадии:

- «Разбить на отдельные стадии (по очереди)»,
- «Объединить со следующей (одновременно)»,
- «Удалить стадию».

### 2.6 Порог экзамена

В инспекторе режима-экзамена поле **«Порог нарушений в группе»** (ползунок; под ним подпись «После N нарушений оставшиеся шаги группы пропускаются»). При достижении порога остаток группы пропускается (шаги получают статус `Skipped`), и экзамен переходит к следующей группе. Если порог = 2, то второе нарушение в группе завершает её.

### 2.7 «Вне очереди»

В инспекторе режима выпадающий список **«Действие вне очереди»**:

- **«Считать нарушением»** — действие раньше очереди записывается как нарушение. В тренировке это попытка шага, в экзамене — провал шага своей группы.
- **«Шаг неактивен до своей очереди»** — действие раньше очереди просто не засчитывается.

### 2.8 Выбор логгера и анализатора

- В инспекторе режима поле **«Анализатор по умолчанию»** — чем оценивается журнал после прохождения этого режима.
- На **Scenario Runner**: «Сценарий», «Логгер» (JSON-файл, в памяти или пусто — журнал только в памяти), «Анализатор» (пусто — «(анализатор режима)»), «Режим при запуске» (по умолчанию «(выбор на экране)»), «Перед стартом сессии» (UnityEvent), «Анализаторы для переоценки».
- Логгер `JsonFileLoggerAsset` пишет в `persistentDataPath/<Папка>/`. Папка настраивается полем `Folder Name` (стандартная подпись Unity).
- Параметры анализаторов правятся на их ассетах: у тренировки — баллы по номеру попытки (по умолчанию 10, 5), у экзамена — «Начальный балл» (100), «Штраф за проваленный шаг» (10), «Штраф за пропущенный шаг» (5).

### 2.9 Подключение кнопки или зоны к событию

К объекту сцены добавьте компонент (Add Component, поиск по имени):

| Компонент | Источник | Поле события |
|---|---|---|
| `ButtonEventSource` | `Button` (нужен на том же объекте) | «Событие при нажатии» |
| `TriggerEventSource` | Collider с включённым Is Trigger | «Событие при входе», «Событие при выходе», «Тег объекта» |
| `CollisionEventSource` | Collider + Rigidbody на одном из объектов | «Событие при столкновении», «Тег объекта» |
| `UnityEventSource` | Любой `UnityEvent` | «Событие» |
| `ToggleStateSource` | `Toggle` | «Состояние» (пишется значение переключателя) |

Для `UnityEventSource`: в любом UnityEvent нажмите «+», перетащите объект и выберите `UnityEventSource.Raise`. Для `Toggle.onValueChanged` выберите динамический bool: `RaiseIfTrue` (событие при включении) или `RaiseIfFalse` (при выключении). Инспекторы источников показывают предупреждения: нет коллайдера, не включён Is Trigger, событие не выбрано, ключ не используется ни одним шагом.

Пустое поле «Тег объекта» — реагировать на любой объект.

### 2.10 Симуляция событий и переоценка в инспекторе раннера

Выделите `Scenario Runner` (в сцене или `Demo/Prefabs/Scenario Runner.prefab`). В Play Mode в секции **«Управление прохождением»**:

- кнопки «▶ <режим>» запускают режим заново, «■ Прервать» останавливает;
- «Режим», «Текущая группа», «Активные шаги» — состояние прохождения, шаги окрашены по статусу;
- **«Симуляция события»**: выберите «Событие» (меню «▾» с разделами «Ждут активные шаги» и «Все события») и нажмите «Отправить» — так, будто его вызвал источник;
- «Журнал — последние N записей» — живая лента.

Секция **«Результаты»**: «Загрузить последний журнал», «Открыть папку журналов», выбор «Анализатор» и «Переоценить» — оценка последнего прохождения или загруженного файла другим анализатором. Тот же функционал есть в окне **Tools → ScenarioKit → Журналы прохождений**.

## 3. Контрольные примеры ТЗ §7

Результаты получены прогоном в Play Mode на демо-сцене. Для воспроизведения удобнее всего симуляция событий в инспекторе раннера (2.10) или реальные кнопки HUD. Игрок стартует в (0, 0, −8); ящик в (0, 0), стена в (3, 0).

### 3.1 Тренировка: 105 / 120

Режим «Тренировка». Максимум 12 шагов × 10 = 120.

1. `power_on` с первой попытки: «Питание». (10 баллов)
2. `push_box`: сначала заденьте стену (`Wall_Hit`, нарушение), затем толкните ящик (`Box_Hit`). Попытка 2. (5 баллов)
3. `signal`: дважды нажмите «Тревога» (два нарушения), затем «Сигнал». Попытка 3. (0 баллов)
4. Остальные 9 шагов чисто, с первой попытки: «Свет», зона C, зона A → зона B, «Насос» (клапан открыт), «Проверка», сфера, зона D, «Отчёт», закройте «Клапан». (9 × 10 = 90)

Итог: 10 + 5 + 0 + 90 = **105 / 120**.

### 3.2 Экзамен: 70 / 100

Режим «Экзамен». Порог — 2 нарушения в группе.

1. Группа «Подготовка»: нажмите «Тревога» (нарушение `power_on`), затем заденьте стену (нарушение `push_box`). Порог достигнут, группа завершается досрочно: `light_on` и `enter_zone_c` получают статус `Skipped`.
2. Группы «Запуск» и «Завершение» пройдите чисто: зона A → зона B, «Насос», «Проверка», сфера, зона D, «Сигнал», «Отчёт», закройте «Клапан».

Итог: 100 − 2 × 10 (проваленные шаги) − 2 × 5 (пропущенные) = **70 / 100**.

## 4. Техническое описание

### 4.1 Поток данных

```
Источники (MonoBehaviour)  →  ScenarioEventBus  →  ScenarioSession  →  журнал  →  анализатор
  Button/Trigger/Collision      (статическая шина      (чистый C#,         (ScenarioLog,     (TrainingAnalyzer,
  UnityEvent/ToggleState         событий + состояние    без Unity API)      IScenarioLogger)  ExamAnalyzer)
                                 мира)
```

- **События** (`Assets/ScenarioKit/Runtime/Events`): `ScenarioEventKey`, `ScenarioStateKey`, `ScenarioEventBus` (шина и состояние мира, `IWorldState`).
- **Источники** (`Runtime/Sources`): превращают действия Unity в события шины.
- **Шаги** (`Runtime/Steps`): `StepDefinition` — данные шага, `StepTracker` — состояние одного шага в сессии, `StepVerdict` — ответ трекера (ничего / прогресс / выполнен / нарушение).
- **Режимы** (`Runtime/Modes`): `ScenarioMode` → `TrainingMode`, `ExamMode`; `StepGroup` → `ActivationStage` → шаги.
- **Сессия** (`Runtime/Execution/ScenarioSession.cs`): чистый C#. Ведёт активацию стадий и групп, обрабатывает нарушения (повтор в тренировке, Failed/Skipped и порог в экзамене), пишет журнал.
- **Раннер** (`ScenarioRunner`): MonoBehaviour, мост между сценой и сессией. Запуск, прерывание, `SimulateEvent`, `Analyze`, `LastLog`, `LastResult`, `CurrentLog`.
- **Журнал** (`Runtime/Logging`): `ScenarioLog`, `LogRecord`, `IScenarioLogger`, `MemoryScenarioLogger`, `JsonFileScenarioLogger`.
- **Анализаторы** (`Runtime/Analysis`): читают только журнал, не сессию.
- **Валидатор** (`Runtime/Validation/ScenarioValidator.cs`): проверяет сценарий, результаты показывает инспектор.

Ядро (сессия, анализаторы, журнал) не использует `MonoBehaviour` и `UnityEditor`. Сборки: `ScenarioKit.Runtime`, `ScenarioKit.Editor` (только Editor), `ScenarioKit.Demo`.

### 4.2 Как добавить новое

- **Новый тип шага.** Создайте класс-наследник `StepDefinition` с атрибутом `[CreateAssetMenu(menuName = "ScenarioKit/…")]`, реализуйте `SuccessEvents`, `IsTriggeredBy(key)` и `CreateTracker()`. Трекер — наследник `StepTracker`: `Handle(key, world)` возвращает `StepVerdict` (`None`, `Progress`, `Completed` или нарушение), `Reset()` сбрасывает прогресс. Тип сразу появится в «＋ Новый шаг» (список типов берётся из `TypeCache`), для него работает общий инспектор. Образец — `Runtime/Steps/EventStep.cs`.
- **Новый режим.** Наследник `ScenarioMode`: `Groups`, `RetryAfterViolation`, при необходимости `ShouldSkipRestOfGroup(n)`. Образцы — `TrainingMode`, `ExamMode`.
- **Новый логгер.** Класс, реализующий `IScenarioLogger` (`Write`, `Complete`), и ассет-наследник `ScenarioLoggerAsset` с `Create(header)`. Образец — `JsonFileLoggerAsset`.
- **Новый анализатор.** Наследник `ScenarioAnalyzer` с `Analyze(ScenarioLog)`, возвращает `AnalysisResult`. Образец — `TrainingAnalyzer`. Подсказка: `LogDigest.Create(log)` сворачивает журнал в факты по шагам.
- **Новый источник.** Наследник `ScenarioEventSource` (или отдельный MonoBehaviour) вызывает `ScenarioEventBus.Raise(key)`. Образцы — `ButtonEventSource`, `TriggerEventSource`.

### 4.3 Контракт журнала

Формат: JSON через `JsonUtility`, `FormatVersion = 1`.

```
ScenarioLog { FormatVersion, ScenarioId, ModeName, StartedUtc, StepIds[], Records[] }
LogRecord   { Time, Type, StepId, Result, Message, Data[{Key, Value}] }
```

`Time` — секунды от старта сессии. Типы записей (`LogRecordTypes`): `ScenarioStarted`, `GroupStarted`, `GroupFinished`, `StepActivated`, `StepCompleted`, `Violation`, `StepFailed`, `StepSkipped`, `ScenarioFinished`, `ScenarioAborted`. Анализатор получает только `ScenarioLog`, поэтому оценить можно любой сохранённый файл и любым анализатором.

`AnalysisResult`: `AnalyzerName`, `Score`, `MaxScore`, `Steps[]` (`StepScore`: `StepId`, `Status` — `Completed`/`Failed`/`Skipped`/`NotCompleted`, `Attempts`, `Points`), `Warnings[]`. Публичные поля — PascalCase, как в DTO журнала.

## 5. Принятые решения

- **«Вне очереди».** В тренировке действие раньше очереди — попытка шага (повтор, штраф баллами). В экзамене — Failed своей группы. Режим может вместо этого просто игнорировать такие действия.
- **Нарушение в экзамене.** `ExamAnalyzer` считает Failed любой шаг, у которого есть нарушения, даже если он потом выполнен.
- **Обработка событий по снимку статусов.** Событие обрабатывается относительно статусов, зафиксированных до его прихода. Шаги, ставшие активными из-за этого же события, его не видят.
- **Одно событие — выполнение и «вне очереди».** Если ждущий (ещё не активный) шаг получил событие, которое уже принял активный шаг в том же событии, «вне очереди» ему не засчитывается. Это нужно, когда одно событие завершает стадию и одновременно относится к следующей.
- **Старт сессии.** Сначала вызывается «Перед стартом сессии» (`onBeforeSessionStart`), затем состояние мира сбрасывается, и тумблеры (`ToggleStateSource`) заново пишут своё состояние. Поэтому начальные значения, заданные в обработчике, не теряются.
- **Результаты.** `StepScore` и `AnalysisResult` — публичные поля PascalCase (`StepId`, `Status`, `Attempts`, `Points`; `AnalyzerName`, `Score`, `MaxScore`, `Steps`, `Warnings`).
- **Живая лента.** `ScenarioRunner.CurrentLog` — заголовок журнала текущей сессии для ленты записей в инспекторе. Сторонний логгер, не пишущий в этот заголовок, покажет пустую ленту.
- **Порядок стадий** меняется кнопками ▲ ▼, а не ручкой перетаскивания. Перетаскиваются шаги.
- **Автотестов нет.** Решение автора. Работа проверялась вручную (ниже).
