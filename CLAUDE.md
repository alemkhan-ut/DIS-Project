# DIS-Project — конструктор учебных сценариев (ScenarioKit)

Тестовое задание: Unity 6000.3.21f1, C#, URP. ТЗ — `Тестовое.docx` в корне, план — `docs/superpowers/plans/2026-11-04-scenario-constructor.md`.

## Обязательные правила

- **Код, файлы, сцены, префабы — строго по [Rules/GuideLine.md](Rules/GuideLine.md).**
- **Все ответы, планы и отчёты — строго по [Rules/OutputFormat.md](Rules/OutputFormat.md).**

## Правила работы

- **Тестов не пишем.** Не создаём тестовые сборки, не применяем TDD и не запускаем Test Runner. Работа проверяется так:
  1. Консоль Unity без ошибок и предупреждений из `Assets/ScenarioKit` (Unity MCP `Unity_ReadConsole`).
  2. Ручной чек-лист задачи в Editor или Play Mode.
- **Git:** локальная ветка `feature/scenario-kit`. Коммит после каждой законченной функциональной части, сообщение на русском.
- **Ничего не пушить и не мержить в `main`** (никаких `git push`, PR или merge), пока пользователь сам не проверит и явно не разрешит.
- `Тестовое.docx` не коммитить.
- Только стандартные пакеты Unity, сторонние ассеты и плагины запрещены (ТЗ §8).

## Применение гайдлайна в этом проекте

- **Неймспейсы** `ScenarioKit.<Область>`: `Events`, `Sources`, `Steps`, `Modes`, `Logging`, `Execution`, `Analysis`, `Validation`, `Demo`. Для редактора — `ScenarioKit.EditorTools`: не `ScenarioKit.Editor`, иначе возникнет конфликт с `UnityEditor.Editor`.
- **Сборки:** `ScenarioKit.Runtime`, `ScenarioKit.Editor` (только Editor), `ScenarioKit.Demo`.
- **Поля:** `[SerializeField] private` с именем `_camelCase`, доступ на чтение — через свойство PascalCase с `=>`. На имена полей опираются кастомные инспекторы (`SerializedProperty`). Поэтому переименовывать поле можно только вместе с инспектором и с `[FormerlySerializedAs]`. Исключение — DTO журнала для `JsonUtility` (`LogRecord`, `ScenarioLog`…): у них публичные поля PascalCase, это формат файла.
- **Константы:** `UNDER_SCORE`, например `LogRecordTypes.SCENARIO_STARTED`. Значения в журнале при этом остаются читаемыми (`"ScenarioStarted"`).
- **События:** суффикс `Event`, например `ChangedEvent`. Обработчик называется `<Имя события>Handler`, на одно событие в классе один подписчик.
- **Методы, возвращающие данные**, называются по этим данным: `GetSteps()`, `GetStatus()`, `GetResultText()`.
- Без `var`, фигурные скобки всегда и с новой строки, `?.Invoke()`, `nameof()`, `string.IsNullOrEmpty()`.
- Одна сущность на файл, включая `enum` и `struct`.
- **Порядок членов класса** — по разделу «Организация» гайдлайна.
- **`GetComponent`** — только в `Awake()`, а класс получает `[RequireComponent]`.
- **Сцена:**
  - всё, что содержит компонент ScenarioKit, и любой элемент UI оформляется как Prefab. Повторы делаются экземплярами, вариации — через Prefab Variant;
  - `new GameObject()` + `AddComponent()` в рантайме запрещены, только `Instantiate` из Prefab;
  - `Find*` в префабах запрещены;
  - имена объектов осмысленные («Zone A Trigger», а не «Cube (1)»).
- **UI:** `CanvasScaler` в режиме Scale With Screen Size, 1920×1080, match 0.5.
- **Ядро** (`ScenarioSession`, анализаторы, журнал) — чистый C# без `MonoBehaviour` и `UnityEditor`.
- **Ввод** только через новый Input System (`Keyboard.current`). Текст — uGUI `Text` с `LegacyRuntime.ttf`.
- Идентификаторы на английском. Всё, что видит пользователь (UI, `[Header]`, `[Tooltip]`, инспекторы, валидатор, README), — на русском.

## Инспектор (главный приоритет UX)

Сценарий собирает человек без навыков программирования, поэтому каждый ассет ScenarioKit получает кастомный инспектор на IMGUI (`ReorderableList` + `DragAndDrop`).

- **Перетаскивание везде.** Списки упорядочиваются drag-and-drop. Шаги переносятся между стадиями и группами, их можно бросать из окна Project.
- **Выбор из списка.** Каждая ссылка на ассет ScenarioKit — выпадающий список всех подходящих ассетов с пунктом «＋ Создать…» и кнопкой «показать в Project».
- **Понятные подписи.** Подписи на русском, перечисления описаны словами. У шага выводится итоговая фраза «Шаг выполнен, когда…».
- **Ошибки сразу.** Ошибки валидатора выводятся `HelpBox` вверху инспектора, проблемная строка подсвечивается.
- **Центр управления.** В инспекторе сценария шаги и режимы правятся встроенными инспекторами.
- **Быстрые действия:** «Все одновременно», «Все по очереди», «Разбить стадию», «Объединить со следующей», «＋ Новый шаг/режим».
- **Undo** для любых правок.
- **Play Mode:** шаги окрашиваются по статусу. У раннера — запуск режимов, симуляция событий, переоценка журнала.
